# 外卖详情识别与悬浮开关

## 用户操作

1. 在系统设置开启“营养流跨应用分析”无障碍服务。
2. 从营养流首页或外卖应用列表打开已支持的外卖 App。
3. 外卖 App 左上角出现“◉ 营养流 / 识别已关”。首次默认关闭，以后记住上次选择。
4. 点击开关开启识别，再进入单个食品详情（或完整的食品规格面板）。页面稳定后展示原有营养分析弹层。
5. 关闭弹层后，同一页面不会因销量、价格等刷新反复弹出；离开详情后再次进入才重新分析。
6. 关闭开关立即收起弹层、取消待执行识别，关闭期间只检查前台应用，不遍历页面文字。
7. 返回营养流、切换到其他 App、最近任务、锁屏时收起两种悬浮层；返回此次外卖会话时恢复开关。
8. 开启后开关显示“等待菜品”“读取中”“已识别”等状态；长按可重新检查当前页面。
9. 系统权限无法开启时，可在营养流外卖应用页选择“开启帮助”。部分 Android 13 及以上手机安装 APK 后需要用户在应用信息中允许受限设置；程序不会代替用户授权。

## 识别边界

- 点击事件仅请求重新检查页面，不会直接用点击文字弹出分析。
- 需要完整的详情/规格信号、购买操作以及唯一且明确的食品名称；首页、搜索结果、店铺菜单、多个食品候选均拒绝。
- 不再只依赖固定的“商品详情”标题：支持独立商品/详情标签、带关闭按钮的食品面板，以及带返回和规格/购物工具栏的详情页。无标题时还需要菜品价格；列表的“选规格”和“去结算”不能单独触发。
- 合并文本中的销量、好评率、价格、购买按钮不会算入菜名；重复标题按菜名归一化。规格区的可选配菜不当成另一个商品，也不直接作为当前食品的忌口证据。
- 只读取此次从营养流打开的支持应用中的可见节点。原生详情面板优先取自身容器，过滤推荐区，避免混入背景菜单。
- 读取窗口时排除自身悬浮层；遍历保留可见子节点，即使其父容器被标为不可见。每次遍历受 1000 节点、24000 字符、40 层和 250 毫秒预算约束，不从截断的容器推断结果。完整的前景详情面板可优先返回。
- 节点失效等运行时异常会被捕获并有限重试，日志仅包含阶段和异常类型，不保存页面内容。这属于防护改进，尚不能证明已定位用户反馈的闪退原因。
- 护肤品、电子产品、餐具、宠物食品等不生成营养表；取消“当前餐品”及任意中文名称的默认兜底。
- 营养值仍是本地分类估算，不是平台实测数据。没有匹配食品词或页面结构不充分时宁可不弹。
- 未识别价格时显示说明，不猜测 25 元，不生成预算搭配，不将未知价格写入日志；可回营养流手动记录。
- `DeliveryLaunch` 使用有效期两分钟的一次性启动标记；失败启动会清除标记。服务重连时可恢复最近 30 分钟内明确启动的外卖会话，轮询不会延长恢复期限，不保存菜品或页面内容。
- 未修改 Manifest、Gradle 配置、NutritionLogStore；MainActivity 本轮只调整无障碍权限检查、设置入口和开启帮助。
- 悬浮功能使用 Android 5.1/API 22 起提供的无障碍悬浮层；API 21 不尝试未经授权的电话悬浮窗。

## 自动检查

使用 JDK 运行 `tests/run-recognition-tests.ps1`（可传 `-JavaHome`），测试纯 Java 识别器、预算缺失处理和详情访问去重。
用例根据录屏里的列表误弹现象以及反馈涉及的美团、京东、淘宝常见详情结构构造，不是从这些 App 实机提取的无障碍节点树，也不是平台兼容认证。

2026-09-17 本轮本地验证：118 项纯 Java 回归检查通过；使用官方 Android 36 API 和项目所需的 ML Kit 编译依赖，全部 9 个 Java 源文件通过 Java 8 目标编译。覆盖无固定标题、规格选项、合并文本、重复菜名、非食品、未知价格、配料证据和关闭后去重。

本轮 APK：`NutriFlow-feature-ai-recognition-v2-20260917.apk`，APK v1/v2 签名校验通过，与上一版测试包签名一致；已核对权限帮助、长按重试和会话恢复代码入包。SHA-256：`95FDCA37A67B60E0FC33357DD5D073C155074F2906BCD0B800C737A019B33216`。文件名包含 `recognition-v2`；不含该标记的旧测试包不包含本轮修复。

本机受限环境中，标准 Gradle Java 编译任务在关闭依赖 ZIP 文件时触发 `AccessDeniedException`。本次改用独立 JavaCompiler 重新编译全部源文件（进程退出释放文件句柄），再由 Gradle 9.7.1 / AGP 9.3.1 完成资源、DEX、签名和 APK 打包；打包阶段排除了已独立完成的 `compileDebugJavaWithJavac`。这不是标准 Gradle 全流程无障碍通过的证明。使用独立的本地测试签名，未提交密钥或更改项目 Gradle 配置。

设备连接工具受到 Windows 用户目录权限限制，尚未完成手机安装和真实外卖 App 验证。`lintDebug` 已尝试，但 Google Maven 的 lint 依赖下载出现 TLS 握手失败，未完成静态检查；不能视为 lint 通过。

## 手机验收（需安装新 APK）

| 场景 | 预期 |
| --- | --- |
| 从营养流打开美团，首次使用 | 左上角显示关闭状态，首页不弹窗 |
| 开启后浏览首页、特价团、商家列表、点菜菜单 | 不出现营养弹窗 |
| 点击鸡腿堡、盖饭、螺蛳粉等单个食品详情 | 页面稳定后展示对应食品估算 |
| 在淘宝/京东打开面霜、粉底、手机、宠物食品 | 不显示营养表 |
| 关闭分析后滚动/刷新同一菜品 | 不反复弹窗 |
| 返回列表停留后再次进入，或进入另一菜品 | 能再次分析，名称与价格对应当前菜品 |
| 页面有配料和下方推荐食品 | 忌口仅使用当前商品证据 |
| 在分析显示期间关闭左上角开关 | 立即收起分析，后续进入详情不再弹 |
| 关闭后重新开启 | 当前食品详情重新检查；列表依然不弹 |
| 开启状态长按左上角开关 | 重试当前菜品，仍不使用列表点击文字作兜底 |
| 无固定详情标题的关闭面板，菜名与销量价格合并 | 有完整食品、价格和购买证据时可识别 |
| 规格面板有鸡蛋、牛肉等可选加料 | 不因多个选项拒绝主菜，不把未选加料当成忌口证据 |
| 系统权限开关灰色或开启无反应 | 开启帮助提供无障碍设置和应用信息入口，需用户操作系统权限 |
| 切换 App、最近任务、锁屏、返回 | 其他界面无残留悬浮层，返回外卖时恢复开关 |
| 页面缓慢加载、没有价格、没有可访问文字 | 不提前误弹；缺价明确提示；无食品证据时不弹 |

尚需在真实设备上验证不同外卖版本的无障碍树。自绘/图片式页面可能没有可读标题；本次未增加截屏 OCR 或在线服务。
